🔄 1. Definisi SDLC & Mengapa SDLC Penting

SDLC (Systems Development Life Cycle) adalah proses bertahap untuk memahami bagaimana sebuah sistem informasi (IS) dapat mendukung kebutuhan bisnis melalui perancangan (designing), pembangunan (building), dan penyerahan (delivering) sistem kepada pengguna.

Membangun sistem informasi sangat mirip dengan membangun rumah: dimulai dari ide kasar, sketsa gambar, cetak biru (blueprint), hingga konstruksi bangunan.

⚠️ 2. Statistik Kegagalan Proyek IS

Mengapa SDLC begitu ditekankan? Karena persentase kegagalan proyek IT/IS sangat tinggi jika dikerjakan tanpa metodologi terstruktur:

  • Standish Group: 42% proyek IS dibatalkan sebelum selesai.
  • GAO (General Accounting Office): 53% proyek IS pemerintah AS ditinggalkan/gagal.
  • IAG Consulting: 80% proyek mengalami pembengkakan waktu (over time), 72% over budget.
  • IBM: 59% proyek meleset dari salah satu kriteria: waktu, anggaran, atau kualitas.

Akar Masalah Kegagalan: Banyak analis mencoba membuat "sistem canggih" tanpa memahami bagaimana sistem tersebut cocok dan memberi manfaat bernilai (value) bagi tujuan organisasi.

📦 3. 4 Fase Utama SDLC & Deliverables

Fase SDLC Pertanyaan Utama Aktivitas Kunci Deliverable (Hasil Dokumen)
1. Planning Why build the system? How to build it? Identifikasi business value, kelayakan (feasibility), pembuatan work plan & staffing. Project Plan (System Request & Feasibility Study)
2. Analysis Who, What, When, Where? Analisis sistem lama (as-is) & baru (to-be), pengumpulan requirement (wawancara/kuesioner). System Proposal (Logical IS Model)
3. Design How will the system operate? Desain arsitektur, interface, database, file spec, & program design (Build, Buy, or Outsource). System Specification (Physical IS Model)
4. Implementation System Delivery Konstruksi (coding/testing), instalasi sistem, dukungan & post-implementation review. Working IS & Maintenance Plan

👔 4. Peran Utama System Analyst

System Analyst adalah agen perubahan (change agent) kunci yang melakukan 3 tugas utama:

  1. Menganalisis situasi bisnis organisasi (Analyze business situation).
  2. Mengidentifikasi peluang perbaikan (Identify opportunities for improvement).
  3. Merancang sistem informasi untuk mengimplementasikannya (Design IS to implement ideas).

💡 5. Poin-Poin Penting & Cara Menghafal

📌 Poin Utama UAS

  • Urutan SDLC: Planning ➔ Analysis ➔ Design ➔ Implementation (PADI).
  • Hasil Planning = Project Plan. Hasil Analysis = System Proposal. Hasil Design = System Specification.
  • System Proposal adalah Logical IS, sedangkan System Specification adalah Physical IS.

🧠 Jembatan Keledai

"P-A-D-I" ➔ Planning ➔ Analysis ➔ Design ➔ Implementation.

"Plan-Prop-Spec-Work" (Urutan Deliverables): Project Plan ➔ System Proposal ➔ System Specification ➔ Working System.

✍️ 6. Contoh Soal UAS & Pembahasan

Soal 1 (Pilihan Ganda)

Dokumen utama (deliverable) yang dihasilkan pada akhir fase Analysis dalam SDLC adalah...

A. Project Plan
B. System Specification
C. System Proposal
D. Working Information System

Jawaban: C. System Proposal

Pembahasan: Fase Analysis menghasilkan System Proposal yang berisi gambaran kebutuhan sistem baru secara logis (logical model).
